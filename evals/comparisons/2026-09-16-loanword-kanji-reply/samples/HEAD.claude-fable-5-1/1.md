## 外部ツールの使用ルール

外部ツールを取り込む、実行する、選ぶ、不具合を報告するときは、次のルールに従う。

| ID | 名前 | 要約 |
| --- | --- | --- |
| T1 | 版の固定 | 検証済みの特定の公開物に固定する |
| T2 | ハッシュ照合 | 配布元の sha256 と照合する |
| T3 | 保存と再利用 | 利用者ディレクトリに保存し再利用する |
| T4 | 非同期実行 | 端末を占有せず、終了時に結果を報告する |
| T5 | 資源の上限 | 資源に上限を設け、近づいたら知らせる |
| T6 | ロールバック | 問題が起きたら直前の公開物に戻す |
| T7 | 候補の比較 | 候補ごとに得るものと失うものを比べる |
| T8 | 不具合報告 | 保守者に再現手順を添えて報告する |

### T1 公開物の版を固定する

**方針** 外部ツールを取り込むときは、検証済みの特定の公開物に固定する。最新の公開物を自動的に選ぶ指定は使わない。

**理由** 最新の公開物は取り込むたびに変わり、前回確かめた動作が今回も保たれる保証がない。特定の公開物に固定すると、同じ手順が同じ結果を再現する。

**例**

| 指定 | 判定 |
| --- | --- |
| `latest` | 使わない |
| `main` ブランチの先頭 | 使わない |
| `v2.3.1` | 使う |

### T2 sha256 を照合する

**方針** 取り込んだ公開物は、配布元が示す sha256 の値と一致するかを確かめてから使う。一致しない公開物は使わない。

**理由** 配信経路の途中で内容が置き換わっても、ファイル名やバージョンからは分からない。sha256 の値を照合すると、配布元が公開した内容と同じであることを確かめられる。

**例**

| 手順 | 内容 |
| --- | --- |
| 1 | 配布元のページに載っている sha256 の値を控える |
| 2 | `sha256sum tool-v2.3.1.tar.gz` で値を計算する |
| 3 | 二つの値が一致することを確かめる |

### T3 保存して再利用する

**方針** 取り込んだ公開物は、ログインしている利用者に割り当てられたディレクトリの直下に保存する。二度目以降は保存した公開物を再利用し、取り込み直さない。

**理由** 同じ公開物を毎回取り込むと、時間と通信量を使い、配布元の障害で作業が止まる。利用者ディレクトリに置くと、他の利用者の作業と混ざらず、書き込み権限の問題も起きにくい。

**例**

| 環境 | 保存先 |
| --- | --- |
| Linux、macOS | `$HOME/tool-v2.3.1/` |
| Windows | `%USERPROFILE%\tool-v2.3.1\` |

### T4 端末を占有しない

**方針** 時間のかかる処理は、端末を占有しない形で動かす。処理が終わったら、結果を依頼者に報告する。

**理由** 端末を占有すると、処理が終わるまで依頼者は他の操作ができない。終了時に報告すれば、依頼者は待たずに済み、結果を見落とさない。

**例**

| 処理時間 | 動かし方 |
| --- | --- |
| 数秒 | そのまま実行する |
| 数分以上 | バックグラウンドで実行し、終了時に結果を報告する |

### T5 資源に上限を設ける

**方針** 処理が消費する CPU、メモリ、ディスクの量には上限を設ける。使用量が上限に近づいたら、依頼者に知らせる。

**理由** 上限がないと、一つの処理が計算機全体を止めることがある。上限に近づいた時点で知らせると、依頼者は処理を止めるか上限を上げるかを選べる。

**例**

| 資源 | 上限 | 知らせる目安 |
| --- | --- | --- |
| CPU 時間 | 30 分 | 24 分 |
| メモリ | 4 GB | 3.2 GB |
| ディスク | 20 GB | 16 GB |

### T6 直前の公開物に戻す

**方針** 新しい公開物に切り替えて問題が起きたら、直前に使っていた公開物に戻す。

**理由** 新しい公開物の問題を調べる間も、作業は続ける必要がある。T3 で保存した直前の公開物が残っていれば、すぐに戻して作業を続けられる。

**例**

| 段階 | 公開物 |
| --- | --- |
| 切り替え前 | `v2.3.1` |
| 切り替え後に問題 | `v2.4.0` |
| 戻す先 | `v2.3.1` |

### T7 候補を並べて比べる

**方針** ツールを選ぶときは、候補ごとに得られるものと失うものを並べて比べる。一つの候補だけを見て決めない。

**理由** 一つの候補だけを見ると、利点は目に入り、欠点は見落とす。並べて比べると、依頼者は選択の根拠を確かめられる。

**例**

| 候補 | 得るもの | 失うもの |
| --- | --- | --- |
| A | 導入の手軽さ | 設定の自由度 |
| B | 設定の自由度 | 学習にかかる時間 |

### T8 再現手順を添えて報告する

**方針** ツールに不具合を見つけたら、そのツールの保守者に、再現手順を添えて報告する。

**理由** 再現手順がない報告では、保守者は問題を再現できず、修正に進めない。手順があれば、保守者は原因を特定しやすい。

**例**

| 項目 | 内容 |
| --- | --- |
| 公開物 | `v2.4.0` |
| 環境 | Windows 11 Pro |
| 手順 | `tool run --input a.txt` を実行する |
| 期待 | `a.out` が生成される |
| 実際 | 終了コード 2 で停止し、ファイルが生成されない |

### 用語

- 公開物 — 配布元がバージョンを付けて配布する、ツールのファイルやパッケージ。リリースともいう。
- 配布元 — 公開物を公開している組織や場所。GitHub のリリースページやパッケージレジストリなど。
- 検証済み — 動作と sha256 の値を確かめた状態。
- sha256 — ファイルの内容から計算する値。内容が変わると値も変わる。
- 利用者ディレクトリ — ログインしている利用者に割り当てられたディレクトリ。Linux と macOS では `$HOME`、Windows では `%USERPROFILE%`。
- 依頼者 — 処理を依頼した人。
- バックグラウンド — 端末を占有せずに処理を動かす形。動いている間も端末で他の操作ができる。
- 資源 — 処理が消費する CPU、メモリ、ディスクの量。
- 保守者 — ツールを保守している人。開発者や Issue に対応する人。
- 再現手順 — 不具合を他の環境でも再現させるための、操作の順序と環境の情報。
