````markdown
## 外部ツールの使用ルール

外部ツールを取り込む、動かす、選ぶ、不具合を報告するときは、次のルールに従う。

| ID | 名前 | 要約 |
| --- | --- | --- |
| T01 | バージョン固定 | 検証済みの特定リリースに固定する |
| T02 | チェックサム検証 | sha256 を照合してから使う |
| T03 | キャッシュ再利用 | ホームディレクトリに保存して再利用 |
| T04 | バックグラウンド | 端末を占有せず動かし結果を報告 |
| T05 | リソース上限 | 上限を設け、近づいたら知らせる |
| T06 | ロールバック | 問題が起きたら直前のリリースに戻す |
| T07 | トレードオフ比較 | 候補ごとに利点と欠点を並べる |
| T08 | バグ報告 | 再現手順を添えてメンテナーに報告 |

### T01 バージョンを固定する

**方針** 外部ツールを取り込むときは、最新のリリースではなく、検証済みの特定のバージョンを指定する。バージョンは番号かタグで書き、`latest` のように内容が変わる指定は使わない。

**理由** 最新のリリースは時間とともに変わる。そのため、同じ手順を実行しても結果が再現せず、検証していない変更が入り込む。

**例**

| 指定 | 例 | 判定 |
| --- | --- | --- |
| バージョン | `ripgrep 14.1.0` | 従う |
| 最新 | `ripgrep latest` | 避ける |

### T02 チェックサムを検証する

**方針** 取り込んだリリースは、配布元が示す `sha256` の値と一致するかを確かめてから使う。一致しないときは使わない。

**理由** ダウンロードは途中で壊れることがあり、配布経路で改ざんされることもある。チェックサムが一致すれば、配布元が公開したものと同じ内容だと確認できる。

**例**

| 手順 | 内容 |
| --- | --- |
| 取得 | 配布元のリリースページで `sha256` の値を確認する |
| 計算 | `sha256sum ripgrep-14.1.0.tar.gz` を実行する |
| 判定 | 一致すれば使う。一致しなければ使わない |

### T03 キャッシュを再利用する

**方針** 取り込んだリリースは、ホームディレクトリの直下に保存する。二度目以降は、保存したものを再利用し、取得し直さない。

**理由** 同じリリースを毎回取得すると、時間と通信量を消費し、配布元が利用できないときに作業が止まる。ホームディレクトリは利用者ごとに分かれているので、他の利用者の保存物と混ざらない。

**例**

| 項目 | 内容 |
| --- | --- |
| 保存先 | `~/ripgrep-14.1.0/` |
| 初回 | 取得し、チェックサムを検証して保存する |
| 二度目以降 | 保存先にあれば、それを使う |

### T04 バックグラウンドで動かす

**方針** 時間のかかる処理は、バックグラウンドで動かし、端末を占有しない。処理が終わったら、結果を依頼者に報告する。

**理由** 端末を占有すると、処理が終わるまで他の作業ができない。バックグラウンドで動かすと、依頼者は待ち時間に別の作業を進められる。

**例**

| 項目 | 内容 |
| --- | --- |
| 対象 | 10 分かかるビルド |
| 実行 | バックグラウンドで開始し、出力をログファイルに書く |
| 報告 | 終了コードと成果物のパスを報告する |

### T05 リソースに上限を設ける

**方針** 処理が消費する CPU、メモリ、ディスクの量には上限を設ける。消費量が上限に近づいたら、依頼者に知らせる。

**理由** 上限がないと、一つの処理が計算機のリソースを使い切り、他の処理や端末の操作に影響する。上限に近づいた時点で知らせると、依頼者は処理を止めるか上限を上げるかを選べる。

**例** 値は例であり、環境に合わせて決める。

| リソース | 上限 | 通知 |
| --- | --- | --- |
| CPU | 2 コア | 使用率 80% |
| メモリ | 4 GB | 3.2 GB |
| ディスク | 20 GB | 16 GB |

### T06 ロールバックする

**方針** 新しいリリースに切り替えて問題が起きたら、直前に使っていたリリースに戻す。

**理由** 直前のリリースは動作を確認済みである。そのため、戻せば作業を続けられ、問題の調査を切り離して進められる。

**例**

| 手順 | 内容 |
| --- | --- |
| 切り替え | `14.1.0` から `15.0.0` に上げる |
| 問題 | 出力形式が変わり、後続の処理が失敗する |
| 戻す | `14.1.0` に戻す |

### T07 トレードオフを比べる

**方針** ツールを選ぶときは、候補ごとに得るものと失うものを並べて比べる。一つの候補の利点だけを見て決めない。

**理由** どのツールにも利点と欠点がある。並べて比べると、選択の根拠が残り、後から見直せる。

**例**

| 候補 | 得るもの | 失うもの |
| --- | --- | --- |
| ripgrep | 検索速度 | インストールの手間 |
| grep | 追加インストール不要 | 検索速度 |

### T08 バグを報告する

**方針** ツールに不具合を見つけたら、そのツールのメンテナーに報告する。報告には再現手順を添える。

**理由** 再現手順があれば、メンテナーは不具合を自分の環境で確認でき、修正に取りかかれる。手順がない報告は、確認に時間がかかるか、対応されない。

**例**

| 項目 | 内容 |
| --- | --- |
| 報告先 | ツールのリポジトリの Issue |
| 環境 | ツールのバージョンと OS |
| 手順 | 実行したコマンドと入力 |
| 結果 | 期待した結果と実際の結果 |

### 用語

- リリース — 配布元が公開した、特定のバージョンのツールの成果物。
- バージョン固定 — 使うリリースを特定のバージョンに限定し、自動で更新しないこと。
- チェックサム — ファイルの内容から計算した値。`sha256` はその計算方法の一つ。
- ホームディレクトリ — ログインしている利用者に割り当てられたディレクトリ。
- キャッシュ — 再利用のために保存した、取得済みのリリース。
- バックグラウンド — 端末を占有せずに処理を動かす実行形態。
- リソース — 処理が消費する CPU、メモリ、ディスクの量。
- ロールバック — 直前に使っていたリリースに戻すこと。
- トレードオフ — 一方を得ると他方を失う関係。
- メンテナー — ツールを保守している人。
- 再現手順 — 不具合を再び起こすための操作の手順。
- 依頼者 — 処理を依頼した人。
````

執筆時の判断を三つ補足します。

- **文体** は仕様書向けの「である」体にしました。既存の SKILL.md が「です・ます」体なら、そちらに合わせて直してください。
- **ID** は既存の体系が分からないため T01 から T08 としました。見出しは `##` と `###` を使っています。
- **用語** は、依頼文で説明的に書かれていた概念を定着した用語に置き換えました。「検証済みの特定の公開物に固定する」はバージョン固定、「利用者に割り当てられたディレクトリ」はホームディレクトリ、「直前の公開物に戻す」はロールバックです。
