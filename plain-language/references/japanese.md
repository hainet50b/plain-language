# 日本語の原則

日本語を書く、編集する、レビューする、または日本語に翻訳するときに、
[共通原則](../SKILL.md)に加えてこれらの原則を適用する。

## 4xx Sentence

### J402 読点で係り受けを変えない

読点は係り受けを示すために打ち、係り受けを変える位置には打たない。打つ
のは、長い修飾語の境界と、語順を入れ替えて前に出した語のあとである。
係り受けが一つにしか読めない位置には、間を取るための読点も打たない
（「サーバーは、リクエストを検証する。」の読点は要らない）。

## 5xx Lexicon

### J502 英語由来の用語の表記を選ぶ

英語由来の専門用語とビジネス用語は、その分野の人が文書、コード、UI、
会話で実際に使う表記で書く。英字が定着していれば英字（Pull Request、
API）、カタカナが定着していればカタカナ（バージョン、ラベル、セクション、
デプロイ）、漢字が定着していれば漢字（非同期、認証）で書く。

英語の語を一語ずつ訳して呼び名を作らない。pricing model は「料金の形」
ではなく「料金体系」、version は「版」ではなく「バージョン」、label は
「札」ではなく「ラベル」と書く。一語ずつ訳した呼び名は、読み手が元の
英語を推測しないと概念を特定できない。迷ったら、その分野の人が仕様書や
会話でその呼び名を使うかで決める。書いたあとにも、この基準で見直す。

## 6xx Orthography

### J605 技術文書で半角と全角を使い分ける

ドキュメントやコードについての回答のような技術的な文章では、数字と英字を
半角で書き、前後に半角スペースを置く（「AI は 3 つの API を呼び出す。」）。
全角の句読点や括弧に接する位置には置かない。記号は係る文字に合わせ、
日本語に係る記号は全角、数字と英字に係る記号は半角で書く（「v2.0」
「3,000」）。小説や随筆では、その文章の書き方に合わせる。
